# Full-evaluation checklist

The platform's 8-item gate (wording copied from the Evaluation page on 2026-10-07; the Submit button stays locked until all are confirmed). One note per item on how we meet it or what is still open.

- [ ] **Smoke test completed** — "The Add/Search API has passed the platform smoke test and is currently usable." *Open:* needs the public deployment (domain, TLS, `MEMORY_API_KEY`) and an issued key; local `scripts/smoke_test.py` passes.
- [ ] **API contract is followed** — "The submitted code and deployed interfaces are wrapped according to the official Add/Search format." *Done in code:* synchronous Add with byte-exact ID echo and `success: true`, idempotent `request_id` (409 on conflicting replay), `data` array never longer than `top_k`, `[]` for unknown users, unauthenticated `/health`; covered by `tests/` (21 tests) and `scripts/smoke_test.py` (run on 2026-10-07 against a key-protected local server: 401 without key, 200 with X-Api-Key/Bearer/Token, 200 on identical replay, 409 on conflicting replay, 422 on a bad body).
- [ ] **Add/Search model rules are understood** — "Open-source Methods entries are expected to use gpt-4o-mini during Add. Commercial Products entries have no Add/Search model restriction." *Our position:* 0.2 uses no model at all; any future LLM is `gpt-4o-mini` only, any embedding `text-embedding-v4` only. *Open:* ask the organisers whether a zero-model entry is acceptable under "expected to use gpt-4o-mini".
- [ ] **Full evaluation capacity confirmed** — "Capacity for storage, bandwidth, and request handling is prepared for the selected track's Full evaluation scale and the entered Add/Search concurrency limits." *Open:* declare 16/16; run a 16-way concurrent soak on the deployed box; budget ≥ 20 GB disk (Textual track ≈ 300 M tokens per the official site).
- [ ] **Deployment information is complete** — "The submitted notes include the deployed API version, endpoints, authentication, capacity, and operational constraints." *Open:* endpoints and domain TBD; the rest is drafted in `docs/SUBMISSION.md`.
- [ ] **Original work is disclosed** — "Any reused paper, repository, or code is attributed with its original authors, technical report, and the changes made; personal work is identified as such." *Done:* `docs/METHOD_CARD.md` + `NOTICE`. The 0.1 draft's lines adapted from the unlicensed FTS5 baseline were rewritten in 0.2 and the history is disclosed in the card; ReFind (MIT) ideas are listed with the notice.
- [ ] **This is a substantive submission** — "It is not a repeated near-duplicate or a low-quality submission intended to occupy evaluation capacity." *Our position:* single system, one version, smoke runs only as needed, one Full run; the method changes relative to the baseline pattern are listed in the card.
- [ ] **No manipulation or cheating** — "The system does not use prompt injection, benchmark leakage, result manipulation, malicious behavior, or other leaderboard abuse." *Done in code:* Search returns stored evidence only (no answer generation, no instructions in `content`), no hard-coded answers, strict `user_id` isolation, no logging or reuse of evaluation data, local tuning only on our own `evalset/`.
